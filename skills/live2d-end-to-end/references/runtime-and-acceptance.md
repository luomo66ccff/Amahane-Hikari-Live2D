# 运行时与验收

本参考处理从导出包到真实网页画面的证据链。Core、浏览器、VTube Studio 和摄像头属于不同边界，必须分别标记状态。

## 1. 真实参数和更新所有权

加载真实模型后枚举参数 ID、min/default/max、Drawable、Part 和服装路由，建立“控制语义—实际 ID—范围—证据—状态”映射。只看到一个 ID、滑块或未报错的 setter 时写 `PRESENT_UNVERIFIED`；只有真实关键形、像素/几何变化、导出和读回闭环才写 PASS。

记录一帧更新顺序：动作、表情、眨眼、外部口型、鼠标跟随、物理和复位各在哪里写值。输入平滑按时间步长计算，钳制到真实范围；暂停应冻结画面，较大时间步、失焦和恢复不能造成跳变。

为冲突通道规定优先级和交还边界。快速点击不能被提示节流吞掉；动作取消后要等真正 idle 再交还 greeting 或外部口型；闭口咀嚼在活动及回收期保留口型所有权；TTL 按墙钟过期；reset/destroy 清掉 pending mouth、动作状态和 writer。眨眼、表情和说话若要混合，写明叠加顺序并用真实浏览器测试。

## 2. Q 弹、手臂和网页控制

在网页中驱动真实参数，不只更新 UI 标签。按用户目标制定固定姿态和连续动作矩阵；若本次目标包含头身反向、嘴部表演、单肩/双肩、多个小动作、咀嚼或多服装换装，就为对应项保留独立证据，未列入目标的功能不要被技能强行添加。手臂的验证重点是肩根—袖根—肘腕—手的连续链和小幅自然摆动；一帧看似 Q 弹但根部漂移、整臂平移或持续同频抖动都不算通过。

开发调试入口可以提供参数扫描、暂停物理/待机、背景切换、动作、咀嚼、肩部、复位和版本信息，但只在开发构建暴露。正式页保留现有跟随、表情、换装、缩放、居中、暂停和打招呼；按钮没有真实绑定时不得包装为已生效。

## 3. Core 加视觉的双门验收

Core 门先确认：模型及资源引用完整；参数范围可读；指定姿态读回值接近目标；旧状态、未改纹理、拓扑、UV、绘制顺序、物理和 Parts 在允许范围内；纹理/模型可加载且无 context loss。使用当前 Core API，先查接口再写收集器；例如不要假定不存在的 `drawables.renderOrders`，应按版本使用公开的 `getRenderOrders()` 或等价接口。

在进入 Core/浏览器测试前，可从仓库根目录运行一次只读的引用闭包检查：

```sh
python skills/live2d-end-to-end/scripts/verify_model_package.py model/runtime/SuJiangXue_HikariSmirk_t001.model3.json --base-dir model/runtime --json
```

它会列出 `FileReferences`（以及其中继续声明的 `FileReferences`）的相对路径、文件大小、缺失项和越界项。脚本不写模型，也不检查 MOC 语义、网格、参数绑定、Core 加载或渲染画面；`ok: true` 不能写成 Core 或视觉 PASS。

视觉门再确认：

- 中性固定帧和原始基准可见，白、黑、中灰背景抽查边缘与隐藏底画；
- 根据本次变更影响列出测试矩阵：受影响通道及其组合必须有固定帧和连续播放证据；共用控制器、资源或更新顺序的下游通道一并回归，未受影响部分保留最小基线抽检。Hikari 的一次历史验收曾覆盖 Head/Body 九宫格、六类嘴部、眼睛闭合、肩部、三种动作和三套服装，这只是该次矩阵示例，不是每个新模型的硬性功能清单；
- 画面由真实 Editor/SDK/浏览器导出，保留原分辨率帧、来源、时间、模型版本和输入轨迹；连续视频要抽查解码帧并标记不是逐帧审阅；
- 若本次目标含多套服装，分别检查比例、上一套状态泄漏、动作/口型/物理残留和释放；单套项目只检查其实际资源路由。窄视口、加载错误、资源释放也要实际检查。

自动像素差只用于定位和回归，不能证明自然透视、身份或动作观感。失败的点编辑报告、错误 crop、旧候选和过期构建都应保留，不能重跑同一位移或把失败改名为 PASS。状态使用 `PASS`、`PARTIAL`、`UNVERIFIED`、`BLOCKED`，并写清样本和未覆盖范围。

## 4. VTube Studio 是独立边界

网页 Core 加载通过后，若目标是 VTube Studio，另建独立验收：确认导出 SDK/MOC 版本与当前 VTS 兼容；在真实 VTS 中导入、重启加载、查看可见模型和日志，读取参数、表情、物理和映射变化。不要修补 moc 头、替换 VTS Core DLL 或把网页参数表当作 VTS 绑定证明。摄像头追踪、麦克风输入、快捷键和宿主自动映射各自单独测试；没测就写 `UNVERIFIED`。本项目最终网页发布记录保留了 VTS/摄像头未重新验收的边界。

## 5. 本项目经验与新项目待验

本项目的 final release 记录了真实 Core/浏览器/网页页面与动作所有权检查，证明的是指定版本、指定浏览器和有限姿态。它没有证明任意设备、所有参数、每个录像帧或 VTS。新项目应先建立最小中性回读，再逐步增加头脸、嘴肩、物理、动作和换装测试；任何阶段缺少真实画面或保存重开证据，都保持待验状态。
