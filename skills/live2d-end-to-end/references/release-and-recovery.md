# 发布、许可与恢复

## 1. 版本化发布

从锁定源码和已验收导出包构建新的版本目录，保留上一版本源、运行包、清单和失败报告。构建前后检查相对资源引用、大小写、MIME、base path、模型路由、哈希清单和第三方 notices；不要覆盖已验收目录，也不要把中间计数当作最终读回。

发布只在用户当前明确授权的目标范围内执行。外部写入前核验实际操作者/机器人身份、仓库和目标版本；技能示例不能硬编码账号、远程主机、私网地址或 token。未经用户当前明确授权，不得换身份、另建公开仓库或扩大写入范围；权限不足时保留可审阅的本地构建或待合并变更。

## 2. 缓存、健康检查和回退

让 JS/CSS、模型路由和纹理采用内容哈希或版本化 URL，确保浏览器不会混用旧 JSON、blob URL 或过期版本字段。发布后从实际 HTTP 读取最终解析 URL、状态、资源版本和关键文件字节；浏览器客户端失败而另一客户端成功时，记录为连接/客户端边界，不能直接判定模型损坏。

将新构建放入独立目录，完成清单核对和桌面/窄屏健康检查后再做原子入口切换。切换、加载、关键交互或最终读回任一步失败，就恢复旧版本；回退命令只针对当前仍指向该版本的条件。保留旧模型、带哈希代码和清单，保证恢复可审计。

## 3. 许可与公开内容

本技能文档按 CC BY 4.0；`scripts/` 下的可移植脚本按 MIT，并保留 SPDX/来源说明。模型、纹理、绑定和预览若有单独署名或禁止 AI/ML 使用条款，继续使用其原许可；“可下载源码”不等于 OSI 意义上的模型开源。Live2D Cubism Core、Framework、着色器和类型声明来自用户提供的官方 SDK，公开技能包不携带 SDK；生成网页若包含运行组件，必须保留适用的上游 notices 和条款。

独立 Skill 包只放必要的文档、可移植脚本和许可证/署名文件，不携带模型、PSD、CMO3/MOC3、模型纹理或 Cubism SDK。模型项目仓库是否公开这些资产，由用户授权、资产许可和发布目标决定；不要因安装本 Skill 而从既有项目仓库盲目移除。无论仓库类型，公开材料都应清理机器绝对路径、私网/本地端点、凭据、账户资料和原始 UI/网络日志；证据报告可以引用版本化相对路径和活动清单，不复制敏感原始记录。

## 4. 具体失败纠正

| 症状 | 最小纠正和证据边界 |
| --- | --- |
| 生成 PNG 声称透明但边缘有棋盘格/白边 | 保留 RAW，回到 Photoshop 原生蒙版、补绘和 Alpha/三底色检查；未通过前不进 Cubism。 |
| Photoshop 脚本调用当前版本不存在的方法 | 保留失败记录，改用当前版本支持的原生动作并独立读回；不要把脚本退出码当作成功。 |
| Cubism 试用/许可或本机通信阻塞保存 | 只走官方授权路径；记录真实阻塞，停止绑定分支并交接具体对象/参数清单，不绕过许可。 |
| 肩部外层包装器造成中性变形，或圆口候选看似可用却破坏身份 | 从上一已验收 CMO3 恢复，清空/撤回候选并以连续纹理 Alpha 和组合画面重新选择；失败探索不进最终能力。 |
| 点编辑报告报错或重复位移 | 先独立读取当前点位确认是否已经写入，再只修报告；不要在未确认前再次点击。 |
| Core 收集器读取不存在的字段 | 对照当前 API，换用公开读回方法；重新跑 Core，再把视觉验收单独执行。 |
| 测试选择器同时点到 canvas 和换装按钮 | 限定到实际按钮元素并复跑；应用模型没有因此改变时，不要制造模型回归结论。 |
| 公网客户端 403、纹理重复加载超时或资源版本不一致 | 用同一公共 URL 的独立客户端和实际浏览器分别读回；保留失败样本，必要时在测试环境固定协议/版本，不能扩大为所有网络已稳定。 |

每次纠正都写“症状—证据—归属层—最小修复—复核命令/画面”。同一原因在没有新证据时不要无限重试；切换路径或标记 `BLOCKED`，并保留可回退版本。

## 5. 本项目经验与待验证步骤

本项目发布记录证明了版本化构建、manifest、真实页面 smoke、动作所有权和旧版回退可以形成闭环；同时明确保留了旧连接超时、有限媒体抽样、模型只到大腿和 VTS 未重验等限制。新项目必须重新确认授权、最终 URL、缓存策略、清单字节和回退条件，不能复制历史发布状态或账号身份。
