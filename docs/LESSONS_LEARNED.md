# 经验复盘

## 模型与美术

- 曲线过大或点位移动过猛会让关节断开。连续画稿配合小幅肩部摆动，比单点大弯折或整块刚体位移更容易保持连接。
- 刚体式假 3D 只会让整张脸一起移动，不能解决遮挡。真实 native 头面变形、眼睑/睫毛、颈部和下颌关系才提供可读的近远层次。
- 枚举到参数 ID 不等于完成绑定。发布控制前要确认真实范围、受影响对象、中性读回和渲染变化。
- 嘴部或肩部修复必须守住未改几何、拓扑、UV、绘制顺序、物理和服装状态。范围门比截图更早发现整模型误改。
- native87 的肩部包装器会造成中性形变，因此被拒绝并回到已有身体链；圆口 83/85/86 方案也被拒绝，后续按纹理 Alpha 证据收敛到 native96 的口腔修复。被拒绝的探索不应冒充最终能力。

## 交互所有权

- 状态提示的节流不能节流动作命令。快速点击曾暴露出提示函数提前返回、导致合法动作丢失的问题。
- 取消有真实的 idle 边界。打断动作后的 greeting 或外部口型交接要等动作真正 idle；在收到 cancel 请求时立即触发会丢 greeting 或制造一帧跳变。
- 闭口轻咀嚼在活跃期和取消回收期拥有嘴部通道；动作 idle 后再交还外部 writer。
- 暂停冻结最终画面，但 TTL 按墙钟过期；reset 和 destroy 必须清掉 pending mouth 与动作所有权。

## QA 与证据

- 失败的点编辑报告是失败证据，不是再次点击同一位移的理由。应从已知快照恢复或重新选择，并独立读回，避免双重位移。
- 错误 crop 可能把待审特征裁掉。保留原分辨率帧，给每个裁图标注来源和时间；报告板是审阅辅助，不是原始证据。
- DEV 与 production build 属于不同证据。记录准确命令、mode、define 和输出目录，不能用生产包冒充 DEV QA 包。
- 同源 blob URL 和过期版本字段曾造成误判。要断言最终解析 URL 和实际资源版本，并把测试基础设施失败与应用失败分开。
- 性能证据要读取真实 `drawModel` 时间戳。无头运行中约 240 的采样率不是产品 240 FPS 保证。

## 恢复与发布

- 删除源码目录可能同时丢失应用、构建和状态。恢复或迁移前要有独立源码归档、已验证运行包和读回报告。
- 恢复时区分 ZIP 基底和明确记录的源码 overlay。兼容重建文件必须标为重建，不能继承字节恢复文件的哈希或来源结论。
- 最终 asset manifest 是身份边界。打包后重新读回文件，哈希只放活动 manifest，不复制到无关文案。
- 保留失败候选和过期报告。清晰的发布历史要说明什么被拒绝以及为什么，而不是把所有中间结果改写成成功。

## 两个具体的排错例子

native102 的新参数是实际 Blend Shape，普通参数关键点操作并不适用。修正参数创建和标签读回后，对目标的两个点各做 Y−3；随后 PowerShell 报告中的数组算术失败。此时不能再执行一次位移，而应独立读回点位，确认编辑已经发生，再单独修报告。

Core 收集器曾直接读取不存在的 `drawables.renderOrders`，应改用当前 API 的 `getRenderOrders()`。修正后才取得 231 个旧状态几何完全一致、8 张纹理字节一致的结果；这仍然需要独立视觉验收，不能把 Core PASS 当作“圆口已经好看”。
